        离线回归与完整 Trace
                一、为什么离线回归阶段最重要
                        最终答案错了，可能是意图、检索、字段、工具、权限、接口、编排或生成任一层的问题；只看“回答是否像人”无法优化。
                        记录 Query、意图、子任务、候选工具、参数、权限、接口结果、RAG 命中、最终答案和用户修改，形成完整 Trace。
                五、排序层
                        召回了，但没有排进最终 Top K。
                离线回归
                        用固定评测集复跑完整链路，比较每次版本变化前后的 Trace 和结果。
                        每个样本都要有输入、标准答案、过程记录和评测结果。
                十一、星辰维度的回归案例
                        用户只会看到最终答案错了。
                        最终 Brief 缺少材料时，需要继续定位是检索、工具、字段、权限还是编排造成的。
        RAG 与 Bad Case 归因
                RAG 约束
                        回答只能基于召回内容。
                        增加业务同义词。
                RAG Trace
                        记录召回文档、切片、得分、排序和最终引用。

        权限、工具调用与异常恢复
                第一步：加载用户权限
                        先确认用户能访问的客户、账户、字段和工具范围。
                第二步：识别意图
                        判断用户是查数据、生成材料、识别机会还是推动任务。
                第三步：工具权限过滤
                        在候选工具进入执行链前完成权限过滤。
                第八步：输出复核
                        对数字、字段、来源、权限和输出结构做最终复核。
                一、工具误调用具体包括什么
                        正确链路：识别意图、选择工具、生成参数、权限校验、执行工具、校验结果、组织答案。
                        可能的错误包括选错工具、参数缺失、字段映射错误、重复调用、越权调用和高风险操作未确认。
                        工具调用错误本质上是工具链路中任一环节发生偏差。
                工具网关
                        统一管理工具 Schema、权限、审计和高风险操作确认。
                错误恢复
                        工具执行失败时保留上下文，识别失败节点并选择重试、降级或转人工。
        Agent 编排、记忆与人机协同
                复杂任务
                        一句话可能需要多个能力共同处理。
                        系统先拆解任务，再按依赖关系调用数据、知识库和材料生成能力。
                Workflow 与 Agent
                        确定、稳定、高频的路径适合 Workflow；开放、复杂、需要动态判断的任务适合 Agent。
                记忆
                        页面上下文属于轻量上下文；跨页面、跨会话的稳定偏好才进入长期记忆。
                        正式查询仍要经过权限、工具和数据校验，不能只依赖记忆。
                多 Agent
                        多 Agent 的难点不只是拆任务，还包括顺序、依赖、冲突处理和最终结果校验。
        项目演进与完整面试话术
                八、你可以把项目演进总结成五个阶段
                        先解决可用，再解决准确、可控、可追溯和可复制。
                你的项目怎么串
                        不能直接说招行使用了 MCP，除非项目确实接入过。
                        可以说明项目使用了与 MCP 相同的工具标准化、权限治理和可观测思路。
                八、60-90 秒完整面试话术
                        从业务目标、用户任务、数据与知识、工具编排、权限控制、离线评测和 UAT 七个方面讲清项目闭环。
        评测集、评测表与 UAT
                UAT
                        UAT 是由真实业务用户在接近生产的场景中验证系统是否满足业务目标和使用要求。
                四、评测集和评测表不是一个东西
                        评测集是用于反复运行的标准样本集合；评测表是记录维度、标准、结论和问题的载体。
                评测标准
                        先设置硬门槛，再计算综合得分。
                        权限、事实和关键数字错误属于硬门槛问题，不能被其他高分抵消。
                九、评测阶段谁参与得更多
                        产品、业务、算法、研发和测试分别对业务目标、标准答案、模型效果、链路稳定和验收结果负责。
                UAT 与离线评测的关系
                        离线评测先保证能力和链路达到可验收水平，UAT 再验证真实业务场景，不是二选一。
        召回指标与检索设计
                指标含义
                        Hit Rate：目标内容是否至少被召回一次。
                        Recall：应该召回的相关内容中实际召回了多少。
                        Precision：召回内容中真正相关的比例。
                        Top K：最终进入生成上下文的候选数量。
                六、招行项目完整案例
                        对结构化数据和非结构化材料采用不同检索路径，再在答案层合并并校验来源。
                数据与检索
                        结构化数据查询走字段和权限校验；非结构化内容走知识库召回、排序和引用。
                        检索负责找到证据，生成负责基于证据组织答案，两者要分开评测。
                Chunk 设计
                        按内容类型设计切片，不把表格、制度条款和长段落用同一种固定长度切分。
                        出现冲突时，按数据来源、更新时间和业务权威级别执行冲突规则。
